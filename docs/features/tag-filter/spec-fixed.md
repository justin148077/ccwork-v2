# 태그 필터 정의서 (확정본)

> `spec-original.md`의 요구사항을 구현 가능한 수준으로 구체화한 문서.
> 선행 기능(`docs/features/tag/`)이 머지된 뒤 나온 후속 기능이며, 그 PRD의 Out of Scope 4장에서 "필터링 기능과 함께" 처리하기로 미뤄둔 두 항목(태그 클릭 시 필터 진입, 노트 목록에 태그 칩 노출)을 이번 범위에 포함한다.

## 기능 개요

노트 목록 위에 존재하는 모든 태그를 칩으로 나열하는 필터 바를 두고, 태그 칩 하나를 클릭하면 그 태그가 붙은 노트만 노트 목록에 보이게 한다.

## 데이터 구조

필터는 서버에 저장되는 데이터가 아니다. `src/types/note.ts`의 `Note.tags: string[]`는 이미 존재하며 변경하지 않는다.

- 필터 대상 태그 목록은 **클라이언트에서 매 렌더 시 `notes` 배열을 순회해 파생**한다(전역 태그 조회 API 없음 — 선행 기능 ADR-2 그대로 유지).
- 선택된 필터 태그는 `App.tsx`에 `selectedNoteId`와 동급의 로컬 `useState<string | null>`로 둔다(값 `null` = "전체"). Context에 넣지 않는다 — CLAUDE.md의 "UI 로컬 상태는 context에 넣지 않는다" 원칙을 그대로 따른다.

## 기능 요구사항

### FR-1. 노트 목록 상단에 태그 필터 바가 노출된다

- 하나 이상의 노트가 `tags`를 가지고 있으면, 모든 노트를 통틀어 등장하는 고유 태그 문자열이 `[전체]` 칩과 함께 가나다(알파벳) 오름차순으로 나열된다.
- 어떤 노트에도 태그가 하나도 없으면 필터 바 자체가 렌더링되지 않는다(조건부 렌더링, 빈 칩 목록을 보여주지 않음).

### FR-2. 태그 칩을 클릭하면 해당 태그를 가진 노트만 노트 목록에 표시된다

- 단일 선택만 지원한다(다중 선택 없음).
- 태그 칩을 클릭하면 그 태그가 선택되고, 이전에 선택돼 있던 태그(있다면)는 자동으로 해제된다.
- `[전체]` 칩을 클릭하면 필터가 해제되고 모든 노트가 표시된다.
- **이미 선택된 태그 칩을 다시 클릭하면 `[전체]`로 되돌아간다**(토글 해제) — [미확정, AI가 임의로 정함]

### FR-3. 필터링된 결과에 따라 "노트 X개" 카운트가 갱신된다

- `NoteList` 상단의 "노트 X개" 문구는 필터 적용 후 실제로 화면에 남은 노트 수를 반영한다.

### FR-4. 노트 카드(NoteItem)에도 해당 노트의 태그가 칩으로 표시된다

- 읽기 전용 — 클릭해도 아무 동작 없음(필터 진입은 상단 바에서만 가능).
- 시각 스타일은 `NoteEditor`의 기존 태그 칩(선행 기능 TAG-1)과 통일한다. 구체적인 재사용 방식은 PRD 단계에서 결정.

### FR-5. 필터 상태는 서버에 저장되지 않고 새로고침 시 초기화된다

- `App.tsx`의 `selectedNoteId`와 동일하게 로컬 상태로만 관리되며, 새로고침하면 `[전체]`로 돌아간다.

### FR-6. 필터링 중인 태그를 가진 노트가 하나도 남지 않게 되면 필터가 자동으로 `[전체]`로 리셋된다

- 노트 삭제, 태그 제거(선행 기능 TAG-2) 등 원인과 무관하게 "현재 선택된 태그를 가진 노트 수 == 0"이 되는 순간 적용한다.

## 유효성 규칙

| 규칙           | 동작                                                                  | 사용자 메시지     |
| -------------- | --------------------------------------------------------------------- | ----------------- |
| 다중 선택      | 지원하지 않음 — 한 번에 하나의 태그만 필터로 적용                     | 없음              |
| 대소문자 병합  | 병합하지 않음 — `React`와 `react`는 필터 바에서 서로 다른 칩으로 표시 | 없음              |
| 정렬           | 가나다(알파벳) 오름차순, `localeCompare` 사용                         | —                 |
| 태그 없는 상태 | 모든 노트에 태그가 하나도 없으면 필터 바 자체를 렌더링하지 않음       | 없음(조용히 숨김) |
| 필터 대상 소멸 | 선택 중인 태그를 가진 노트가 0개가 되면 자동으로 `[전체]`로 리셋      | 없음(조용히 리셋) |

## 엣지 케이스

- **`tags` 필드가 없는 레거시 노트**: 필터 대상 태그 목록을 만들 때 `note.tags ?? []`로 방어. 필터 바 구성에 영향 없음.
- **필터 적용 중 새 노트 작성**: `[새 노트]` 버튼으로 작성 중인 노트는 저장 전까지 `NoteList`에 애초에 나타나지 않으므로(기존 동작), 필터와 별도의 상호작용이 없다. 필터 상태 자체는 유지된다.
- **필터로 목록에서 사라진 노트가 이미 `NoteEditor`에 열려 있는 경우**: 편집 화면은 닫히지 않고 계속 열려 있다 — `selectedNoteId`와 필터는 독립된 로컬 상태라는 기존 아키텍처(CLAUDE.md)를 그대로 따른다. [미확정, 기존 아키텍처에서 유추함 — 확인 필요]
- **이미 선택된 태그 칩을 다시 클릭**: `[전체]`로 토글 해제(FR-2 참고).

## 용어 정의

| 용어      | 정의                                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------------------- |
| 선택      | 필터 바에서 태그 칩을 클릭해 그 태그를 필터 조건으로 삼는 것. 서버에 아무것도 기록하지 않는 순수 UI 상태 변경 |
| `[전체]`  | 필터가 해제된 기본 상태를 나타내는 특수 칩 — 모든 노트를 보여준다                                             |
| 대상 소멸 | 필터링 중인 태그를 가진 노트가 0개가 되어 필터를 유지할 근거가 사라지는 것 (FR-6)                             |

이 문서에서 "선택"은 선행 기능(`docs/features/tag/spec-fixed.md`)의 "확정"(Enter로 칩이 되는 것) · "반영"(저장으로 서버에 기록되는 것)과 다른 개념이다 — 필터의 "선택"은 서버 기록이 전혀 없는 순수 클라이언트 상태 변경이다.

## 이번 범위에서 제외

- 다중 태그 동시 필터(AND/OR 조합)
- 태그 자동완성(입력 중 제안)
- 태그별 노트 개수 표시(칩 옆 숫자 배지)
- URL 쿼리 파라미터 등 공유 가능한 필터 링크
- 텍스트 입력으로 태그 검색(칩 클릭 방식만 지원)
